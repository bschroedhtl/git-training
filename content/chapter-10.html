10  Exercises

Work in pairs (person A and person B).

  1. Setup: both of you set up Git (chapter 2). Check your settings with git config --global --list.
  2. First commits: person A creates a new repository on GitHub and adds person B as a collaborator. Both of you clone it. Each of you creates a file with your name, commits it and pushes it. Look at the history with git log --oneline.
  3. Rejected push: both of you change a different file without pulling first. Person A pushes, then person B pushes. What happens? Fix it with git pull and git push.
  4. Merge conflict: both of you change the same line in the same file. Person A pushes first. Person B pulls and solves the conflict in VS Code.
  5. Branch and pull request: person A creates an issue “Add a README”. Person B creates a branch for it, writes the README, commits with closes #<number> and opens a pull request. Person A reviews and merges it. Is the issue closed now?
  6. Undo: change a file and throw the change away with git restore. Make a commit, push it and undo it with git revert.
  7. Committed by mistake: create a folder node_modules with a file in it, commit and push it. Remove it from the repository with .gitignore and git rm -r --cached. Check that the folder is still on your disk, but gone on GitHub.
  8. Time travel: look at the project as it was two commits ago with git switch --detach HEAD~2. What does git status say? Go back with git switch main. Then get one file back from two commits ago with git restore --source=HEAD~2 <file> and commit it.

Practice more on https://learngitbranching.js.org. It shows what happens to your branches as a picture.
